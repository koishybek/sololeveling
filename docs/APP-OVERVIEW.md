# Олжас E-Rank — полное описание приложения

> Единый контекст-документ для скармливания ИИ. Описывает ЧТО это, КАК устроено,
> и ПО КАКИМ ПРАВИЛАМ работает. Актуально на 2026-06-27.

---

## 1. Что это такое (в двух словах)

**Олжас E-Rank** — персональный PWA-трекер калорий с ИИ-распознаванием еды
(клон Cal AI / Calzen), на который сверху надет игровой слой в стиле аниме
**«Поднятие уровня в одиночку» (Solo Leveling)**: ранги E→S, характеристики
СИЛА/ИНТ/ВОЛЯ, ежедневные квесты, «Система», которая ведёт игрока к цели.

- **Единственный пользователь** — Олжас (сам разработчик), Астана. Личный пет-проект.
- **Основная задача пользователя** — сбросить вес (100 → 90 кг), удерживая
  дисциплину через игровую мотивацию.
- **Философия еды:** ИИ только *определяет* блюдо и граммы; калории/БЖУ берутся
  из базы продуктов или из честной ИИ-оценки — числа не выдумываются «на глаз».
- **Голос-первый ввод:** можно надиктовать что съел голосовым сообщением.

**Живёт в проде:** https://sololeveling-amber.vercel.app (Vercel).

## 3. Архитектура

**Local-first, клиент-центричный.** Данные пользователя живут только в IndexedDB
браузера. Бэкенда с БД нет. Синхронизации между устройствами нет.

- **Рендер только на клиенте:** `src/app/page.tsx` грузит приложение через
  `dynamic(() => import("./app-root"), { ssr: false })`, чтобы Dexie никогда не
  попадал на сервер.
- **Route handlers (`/api/*`) — тонкие прокси к OpenAI и базам еды.** Они не
  хранят состояние; вся бизнес-логика игры и данных — на клиенте.
- **Игровой движок чистый и производный:** `computeGame(...)` — чистая функция,
  которая выводит весь RPG-стейт (уровень, ранг, статы, квесты) из уже
  залогированных данных. Отдельно пишутся только: распределённые очки статов и
  выполнение привычек/бонус-квестов.
- **Ключевое правило надёжности:** НИКОГДА не писать в БД внутри observer-а
  `useLiveQuery` (это ридер). Все записи-инициализации — в `useEffect`. Нарушение
  этого правила ранее роняло приложение.

**Деплой:** `.env` в `.gitignore` и в прод НЕ уезжает. `OPENAI_API_KEY` задан как
переменная окружения в Vercel (production/preview/development). Редеплой:
`vercel --prod --yes` из корня проекта.

## 4. Модель данных (Dexie, база `erank`)

Версии схемы: v1 (база) → v2 (вода) → v3 (привычки) → v4 (ИИ-Система).

| Таблица | Ключ | Назначение |
|---|---|---|
| `profile` | `id` (всегда `"me"`) | Профиль пользователя (пол, возраст, рост, вес, цель, активность) |
| `foods` | `id` | Кэш продуктов (per-100g макросы, источник, штрихкод, избранное) |
| `logEntries` | `id` | Записи съеденного (снимок макросов на порцию) |
| `weights` | `date` | Замеры веса по дням |
| `dailyGoals` | `date` | Дневная норма ккал/БЖУ |
| `settings` | `id` (всегда `"app"`) | Настройки: ИИ-модели, цель воды, распределённые очки статов и т.д. |
| `mealPhotos` | `id` | Фото приёмов пищи (Blob) |
| `water` | `date` | Выпитая вода (мл) за день |
| `habits` | `id`, `order` | Кастомные ежедневные привычки/дейлики (жизнь-RPG) |
| `habitLog` | `id`, `date`, `habitId` | Отметки выполнения привычек по дням |
| `system` | `date` | Кэш дневного ИИ-фида «Системы» (уведомления + бонус-квест) |

### Основные сущности

**Profile** — `sex`, `age`, `heightCm`, `weightKg`, `targetWeightKg`,
`activity`, `goal` (`lose`/`maintain`/`gain`), `dailyAdjustmentKcal`.

**FoodItem** — `name`, `source` (`usda`/`off`/`estimate`/`custom`), `per100g`
{kcal, proteinG, carbG, fatG}, `isWholeFood`, `favorite?`, `barcode?`, `brand?`.

**LogEntry** — `date`, `meal` (`breakfast`/`lunch`/`dinner`/`snack`),
`foodName`, `grams`, снимок макросов, `dbSource`, и **RPG-сигналы**:
`correctionMade` (пользователь поправил оценку ИИ), `isWholeFood` (цельный продукт).

**Habit** — `name`, `emoji`, `stat` (`STR`/`INT`/`WIL`), `kind` (`bool`/`count`),
`target?`, `unit?`, `xp`, `archived`, `order`.

**SystemFeed** — `date`, `notices: string[]`, `bonusQuest` {title, detail, xp, stat},
`bonusDone`.

Экспорт/импорт всех данных — JSON-бэкап версии 4 (включает всё, кроме фото).

## 5. Экраны и навигация

Нижняя навигация из 3 вкладок + центральная кнопка «+»:
**📒 Дневник · ⚔️ Статус · (＋) · 📈 Прогресс**.

### 5.1 Онбординг (первый запуск)
Пошаговый квиз с прогресс-баром: цель → пол → возраст → рост → вес →
(целевой вес, если не «поддержка») → уровень активности → (скорость прогресса
со слайдером дефицита 250–1000 ккал/день и живой проекцией даты достижения цели)
→ анимация «Готовим план…» → **раскрытие дневной нормы** (кольцо ккал + БЖУ) →
кнопка «Начать путь E-ранга». Сохраняет профиль, дневную цель и стартовый вес.

### 5.2 Дневник (Dashboard) — вкладка «📒»
- Навигация по дням (стрелки ‹ ›), заголовок «Сегодня»/дата, подпись ранга+уровня.
- **Кольцо калорий** (осталось / перебор), строка `съедено / норма`.
- **Полоски БЖУ** (белки/углеводы/жиры vs цель).
- **Карточка воды** с кнопками +250 / +500 мл.
- **Приёмы пищи** (Завтрак/Обед/Ужин/Перекус): списки записей, тап по записи →
  редактирование, ✕ → удаление.
- ⚙ вверху → Настройки.

### 5.3 Добавление еды (лист по кнопке «+»)
Пять способов ввода, все ведут к редактируемым «черновикам» перед сохранением:
1. **📷 Фото** — снимок/выбор → `/api/scan` (GPT-4o зрение) → список блюд+граммы.
2. **🎤 Голос** — запись с микрофона → `/api/transcribe` (Whisper) → текст →
   `/api/parse-food` → блюда.
3. **⌨️ Текст** — «200 г куриной грудки и рис» → `/api/parse-food` → блюда.
4. **🔍 Поиск в базе** — Open Food Facts (точные числа для брендов).
5. **▦ Штрихкод** — камера (Quagga2) → `/api/food/barcode` → продукт.
   Плюс **избранное** и **недавние** для ре-лога в один тап.

Черновик: можно править граммы/приём пищи/способ готовки перед «Добавить N».
Правка = сигнал `correctionMade` (даёт RPG-очко ИНТ — «обучение Системы»).

### 5.4 Статус (RPG) — вкладка «⚔️»
Главный игровой экран. Панели сверху вниз:
- **⟦ СТАТУС ⟧** — ранг (крупно), уровень, имя «Олжас», титул, полоса EXP,
  три статы СИЛА/ИНТ/ВОЛЯ с полосками и кнопками «+» для вложения очков.
- **⟦ ЖУРНАЛ СИСТЕМЫ ⟧** — ИИ-генерируемые уведомления «Системы» по реальным
  данным + персональный **бонус-квест дня** (кнопка «Принять задание», ↻ обновить).
- Плашка **стрика / штрафа** (🔥 серия дней или ⚠ тайм-аут).
- **⟦ ЕЖЕДНЕВНОЕ ЗАДАНИЕ ⟧** — 5 квестов из еды (см. движок).
- **⟦ ПРИВЫЧКИ ⟧** — кастомные дейлики с чекбоксами.
- **⟦ НЕДЕЛЬНЫЙ ВЫЗОВ ⟧** — 3 недельных челленджа с прогрессом.
- **⟦ ВРАТА ⟧** — весовые «врата» D/C/B/A по кг.

### 5.5 Прогресс — вкладка «📈»
- Плитки: текущий вес / цель / до цели.
- Ввод веса на сегодня.
- **График динамики веса** (Recharts LineChart).
- **График калорий за 14 дней** (BarChart, столбцы зелёные если в норме, красные
  если перебор, пунктир = цель).
- Плитки средних (ср. ккал, ср. белок, дней залогировано, % в норме).
- **Календарь консистентности за 5 недель** (heatmap: в норме / перебор / нет лога).

### 5.6 Настройки (лист по ⚙)
- **Профиль и цель** — правка всех полей, «Пересчитать план».
- **AI-модели (OpenAI)** — переопределение моделей зрения/текста.
- **Дейлики Системы** — добавить/удалить кастомные привычки (выбор стата STR/INT/WIL).
- **Данные** — экспорт/импорт JSON-бэкапа, полный сброс.

## 6. Пайплайн логирования еды (принцип точности)

```
Фото/Голос/Текст ──► OpenAI определяет { блюдо, граммы, способ готовки, оценка per-100g }
                      │
                      ├─(по умолчанию)─► используем ИИ-оценку макросов (source="estimate",
                      │                   честная метка «оценка ИИ»)
                      │
Поиск / Штрихкод ─────┴─► Open Food Facts даёт точные per-100g (source="off")
                      │
                      ▼
        Пользователь правит граммы ──► scaleMacros(per100g, grams) ──► LogEntry
```

**Важно:** ИИ НЕ авто-подбирает брендовый продукт из базы по фото — неверное
совпадение хуже честной оценки. Точные числа — только через явный поиск/штрихкод.

**Источник базы еды:** USDA FoodData Central **недоступна из сети пользователя**
(поэтому используется Open Food Facts). USDA задействуется только если задан
реальный `USDA_FDC_API_KEY`. OFF-данные фильтруются (отбрасываются kcal>900 —
битые общественные данные / кДж, помеченные как ккал).

## 7. Расчёт нормы калорий (чистая математика, покрыта тестами)

`src/lib/nutrition/calories.ts`:

1. **BMR** (базовый метаболизм) — формула **Mifflin-St Jeor**:
   `10·вес + 6.25·рост − 5·возраст + (муж: +5 / жен: −161)`.
2. **TDEE** = BMR × коэффициент активности
   (sedentary 1.2 / light 1.375 / moderate 1.55 / very 1.725 / extreme 1.9).
3. **Цель по ккал** = TDEE − дефицит (похудеть) / + профицит (набор) / без изменений (поддержка).
4. **БЖУ** из ккал по сплиту **30% белок / 40% углеводы / 30% жир** (Атвотер: Б/У=4, Ж=9 ккал/г).
5. **Прогноз:** ~7700 ккал ≈ 1 кг жира → скорость кг/неделю и проекция даты цели.

## 8. ИИ-интеграция (OpenAI под капотом)

Клиент: `src/lib/ai/openai.ts` — ленивый серверный клиент, бросает ошибку если
нет `OPENAI_API_KEY`. Модели переопределяемы через env/настройки:

| Задача | Модель по умолчанию | Где |
|---|---|---|
| Зрение (фото еды) | `gpt-4o` | `identifyFoodFromImage` |
| Текст (разбор блюд) | `gpt-4o-mini` | `parseFoodFromText` |
| Речь (голос → текст) | `whisper-1` | `transcribeAudio` |
| «Система» (журнал) | `gpt-4o-mini` | `generateSystemFeed` |

Все ответы — **строгий structured output** (JSON Schema, `strict: true`).

**API-роуты (`src/app/api/`):**
- `POST /api/scan` — `{ image: dataUrl }` → `{ items[] }` (зрение).
- `POST /api/transcribe` — multipart `{ audio: File }` → `{ text }` (Whisper).
- `POST /api/parse-food` — `{ text, model? }` → `{ items[] }`.
- `POST /api/system` — `{ snapshot, model? }` → `{ notices[], bonusQuest }`.
- `GET /api/food/search?q=` — `{ foods[], source }` (OFF, опц. USDA).
- `GET /api/food/barcode?code=` — `{ food }` (OFF) или 404.

Ошибки сети/оффлайн на клиенте маппятся в человеческое «Нет соединения с
интернетом», а не сырое «Failed to fetch».

## 9. RPG-движок (Solo Leveling) — все правила

Чистая функция `computeGame(...)` в `src/lib/game/engine.ts`. Всё выводится из
логов еды + привычек + бонус-квестов.

### Опыт, уровни, ранги
- **XP:** 20 за каждый выполненный квест/привычку/дейлик.
- **Уровень:** `floor(totalXp / 100) + 1` (100 XP = уровень).
- **Ранги по уровню:** E (1–4) → **D** (≥5) → **C** (≥10) → **B** (≥15) →
  **A** (≥20) → **S** (≥25).
- **Титул** зависит от ранга (напр. E = «Тот, кто выжил после 3-дневной курицы»,
  S = «Монарх Возвышения»).

### Характеристики (статы)
СИЛА (тело/белок) · ИНТЕЛЛЕКТ (точность/знания) · ВОЛЯ (дисциплина/стрик).
Каждый выполненный квест даёт +1 к своему стату. Плюс на каждый уровень
начисляется **+3 очка** для ручного распределения (`availablePoints`).

### 5 ежедневных квестов (из еды за день)
1. **meals** (ВОЛЯ) — залогировать завтрак+обед+ужин.
2. **protein** (СИЛА) — добрать ≥90% нормы белка.
3. **cap** (ВОЛЯ) — уложиться в норму калорий.
4. **correct** (ИНТ) — поправить оценку ИИ («обучить систему»).
5. **whole** (ИНТ) — съесть цельный продукт.

### Привычки (жизнь-RPG, кастомные дейлики)
Дефолтные сиды (у пользователя): 🏃 10 000 шагов (СИЛА), 💻 2 ч кодинга (ИНТ),
🏋️ тренировка/зал (СИЛА), 🧘 0 PMO (ВОЛЯ), 🚫 0 пива/срывов (ВОЛЯ).
Выполнение даёт XP и +1 к стату так же, как квесты. Управляются в Настройках.

### Стрик и штраф
- **Стрик** — сколько дней подряд был выполнен хотя бы один квест из еды.
- **Штраф (тайм-аут)** — если есть история, но сегодня НИЧЕГО не сделано
  (ни еды, ни привычек) → активен штраф (как в аниме: «Обнаружено бездействие»).

### Врата (весовые цели)
Гейты для похудения по кг: **D 95 · C 90 · B 85 · A 80**. «Открыты», если текущий
вес ≤ порога. Показывается ближайшие «врата» и сколько кг осталось.

### Недельные вызовы (за 7 дней)
1. Логировать каждый день (7/7).
2. 5 дней в норме калорий.
3. 5 дней добить белок.

## 10. ИИ-Журнал Системы (главная «фишка под капотом»)

`src/lib/ai/system.ts` + `/api/system` + хук `useSystemFeed`.

OpenAI играет роль **«Системы» из Solo Leveling** — холодного надзирателя. По
компактному снапшоту игрока (ранг, уровень, стрик, штраф, % калорий и белка за
сегодня, вес vs цель, статус привычек) генерирует:
- **2–3 коротких уведомления** в стиле голо-окон Системы
  (напр. «[Серия: 4 дня] Дисциплина закрепляется.»).
- **1 персональный бонус-квест** нацеленный на слабое место игрока
  (низкий белок / перебор / невыполненная привычка / застой веса), награда +20…40 XP
  и стат STR/INT/WIL.

Фид **кэшируется на день** в таблице `system` (генерируется один раз, есть ↻).
Принятие бонус-квеста вливает XP и стат в движок через параметры
`computeGame({ bonusXp, bonusStats })`. Оффлайн → мягкое сообщение, без падений.

## 11. Иммёрсия (звук и вибро)

`src/lib/fx.ts` — синтезированный «звук Системы» через WebAudio (без аудио-файлов):
`ping("quest" | "levelup" | "penalty")` и `haptic(pattern)` через `navigator.vibrate`.
Срабатывают на выполнении квеста/привычки, принятии бонус-квеста и повышении уровня
(есть оверлей-празднование level-up с базлайном в `settings.lastSeenLevel`).

```
    plan.ts, hooks.ts, fx.ts, id.ts, utils.ts
  components/ui.tsx        — примитивы (Button, Card, Sheet, ProgressRing, …)
public/{sw.js, manifest.webmanifest, icon-*} — PWA
docs/                      — research, spec, этот overview
```

PWA: service worker (`public/sw.js`) кэширует оболочку офлайн, но **всегда
пропускает `/api/*`** в сеть (ИИ-вызовы не кэшируются).

## 14. Правила и особенности (важно для доработок)

- **Не писать в БД внутри `useLiveQuery`** — только в `useEffect`.
- **`.env` не деплоится** — ключ OpenAI живёт в env-переменных Vercel.
- **Не собирать (`npm run build`) пока старый `next start` держит тот же `.next`
  порт** — портит `.next` → 500; сначала убить процесс.
- **Тесты:** движок и питание покрыты Vitest (`fake-indexeddb` для БД); E2E в
  реальном Chromium прогоняет онбординг → лог еды (реальный OpenAI) → перезагрузку
  → проверку персистентности → Статус/Систему.
- Всё однопользовательское; авторизации/мультиюзера нет.
